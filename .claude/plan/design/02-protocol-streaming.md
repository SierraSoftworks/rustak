I have enough verified material now. Summary of what the exploration added beyond the brief (all from the public protocol spec in `atak-civ/takproto`, commoncommo, TAK Server, and node-tak, read for facts only):

- ATAK client constants: pings after 15 s idle, repeats every 4.5 s, drops at 25 s; negotiation timeout 60 s both for "no `t-x-takp-v` seen" (continues XML) and "no `t-x-takp-r`" (reconnects); client rx buffer is 64 KiB (`rxBufSize = maxUDPMessageSize = 65536`), which is why TAK Server substitutes >64 KiB protobuf; client resyncs on bad magic and on varint > buffer.
- TAK Server outbound proto `MAX_SIZE = 65536`; inbound bad magic -> `forceClose` (no resync).
- Public `.proto` field table also has `Detail.extensionDetails = 8` (`repeated ExtensionEncodedDetail {extensionId=1 uint32, data=2 bytes}`) and `TakControl.contactUid = 3`, `extensionIds = 4`; TAK Server's `TakMessage` adds `submissionTime = 3`, `creationTime = 4`. We should reserve/pass-through these.
- TAK Server's converter extracts the *first* `<contact>` etc. (`element(name)`) and coerces bad numbers to 0; the spec says do neither. We follow the spec (extract only when exactly one element and strict parse succeeds), which is compatible with both decoders.
- Proto->XML on TAK Server emits typed elements first, then xmlDetail children; xmlDetail element of a typed name replaces the typed one.
- CloudTAK/node-tak: strips `[\u000B-\u001F\u007F-\u009F]` (so never emit `\r`), regex `<event[ >]...</event>` non-greedy, pings every 5 s, needs `t-x-c-t-r` to mark the connection open, reads `TakServerVersionInfo/@serverVersion` from `t-x-takp-v`; `clientEndPoints` items need `callsign, uid, username, team, role, lastStatus`; contacts need `filterGroups, notes, callsign, team, role, takv, uid`.
- Local registry has current stable: quick-xml 0.42, prost/prost-build 0.14, protox 0.9, rustls 0.23.45, tokio-rustls 0.26.5, tokio-util 0.7.19, bytes 1.12, tokio-rusqlite 0.8/rusqlite 0.40, x509-parser 0.18, rcgen 0.14, fixedbitset 0.5, proptest 1.11, arbitrary 1.4.

# rustak M1 plan: protocol + streaming core

## 0. Cross-cutting decisions

| Topic | Decision |
|---|---|
| Detail model | Ordered node tree (`Element`/`Text`/`CData`/`Comment`), attribute order preserved, values stored unescaped. Fidelity is *semantic* (names, order, values, text), not byte-for-byte whitespace; whitespace-only text nodes between elements are dropped. |
| `Event.point` | Required (`Point`). XML without `<point lat lon>` fails parse with `ParseError::MissingPoint`; connection drops it with a metric (matches TAK Server's drop filter). |
| Typed-detail extraction for proto | Spec-strict: replace element only if exactly one element of that name exists, has exactly the expected attribute set, no children, and all numeric attrs parse. Otherwise it stays in `xmlDetail`. On decode, xmlDetail wins on name conflict. |
| Wire encodings | Outbound XML: `<?xml version="1.0" encoding="UTF-8"?>\n<event …>…</event>` (never self-closing `<event>`, `<detail>` omitted when empty, no `\r`, no trailing newline). Proto: `0xBF` + LEB128 length + `TakMessage`. Inbound cap 8 MiB for both; resync on bad magic/varint. |
| Encoding cost | `EncodedEvent` (in rustak-cot) lazily serialises XML and proto once per relayed message and is shared as `Arc` across all recipients. |
| Concurrency | `Hub` = `parking_lot::RwLock<Registry>` with short, never-across-await critical sections; routing runs on the sending connection's task; delivery is `mpsc::Sender::try_send` into bounded per-connection queues. No central actor (rationale in section 2.6). |
| Server-generated times | Millisecond resolution everywhere (`CotTime` = i64 ms). |
| Clean-room proto | One file `rustak-cot/proto/tak/v1.proto`, package `atakmap.commoncommo.protobuf.v1`, written from the field table; reserve 3/4 in `TakMessage`; define `Detail.extensionDetails = 8` as opaque pass-through. |

### 2.2 Connection lifecycle (order matters)

1. Accept; TLS handshake (TLS) or `preauth` (TCP) -> `Principal` (+ leftover bytes seeded into the read codec's buffer).
2. `hub.register(Subscription::new(..))` -> `ConnId`; spawn writer.
3. `replay::replay_latest_sa` (XML, since the writer starts in XML).
4. If `negotiate_protobuf` -> `Negotiation::offer` sends exactly one `t-x-takp-v` (uid = fresh UUID).
5. Read loop. `t-x-takp-q` handled in the connection (needs codec access), all other control/CoT via `Router`.
6. Idle timer (`idle_timeout`) resets on any inbound frame; server never pings.
7. Exit on EOF/error/idle/`Outbound::Close`: abort writer, `hub.unregister`, `notify::on_disconnect`.

### 2.3 `cot_store` interaction

`cot_store/mod.rs`: `#[derive(Clone)] pub struct CotStoreHandle { tx: mpsc::Sender<StoreOp>, dropped: Arc<AtomicU64> }` with `pub fn record(&self, enc: &Arc<EncodedEvent>)` (`try_send`; never blocks the router). `cot_store/writer.rs`: single task owning `tokio_rusqlite::Connection`; drains up to 256 ops or 50 ms, one transaction: `INSERT INTO cot_latest(uid, type, callsign, event_time, stale, xml, updated_at) ... ON CONFLICT(uid) DO UPDATE`, and `INSERT INTO cot_history(uid, type, event_time, xml)` for non-`t-x-*` types when `retention.history_enabled`. `cot_store/latest.rs` read API (`latest_xml(uid)`, `latest_events(since, types)`) for `/Marti/api/cot/xml/{uid}` and `sync`. `cot_store/retention.rs`: `DELETE FROM cot_history WHERE event_time < ?` in a job (`jobs/retention.rs`). Migration `db/migrations/000X_cot_store.sql`: indexes `cot_history(uid, event_time)`, `cot_history(event_time)`. Stored XML is the relayed form (marti stripped, flow tag present).

`auth/principal.rs`: `pub struct Principal { pub username: String, pub user_id: Option<UserId>, pub device_id: Option<DeviceId>, pub kind: PrincipalKind { Person, Service, Anonymous }, pub groups: GroupSet, pub group_names: Vec<GroupRef> }`. `auth/resolve.rs`: `#[async_trait] pub trait CertPrincipalResolver { async fn resolve(&self, cert: &CertificateDer<'_>) -> Result<Principal, AuthError>; }` (x509-parser: CN -> username, serial/fingerprint -> device; M1 test impl maps CN -> user + configured groups). `identity/credentials.rs`: `#[async_trait] pub trait Authenticator { async fn authenticate(&self, username: &str, password: &str) -> Result<Principal, AuthError>; }`.

### 2.5 Fan-out cost

N≈50 connections, SA every ~3 s per client -> ~17 inbound msg/s -> ~850 deliveries/s. Per delivery: one `Arc` clone + `try_send`; per message: one XML and (if any proto peer) one proto serialisation, done lazily by the first writer that needs it. Lock hold time is a hash-map scan of 50 entries. This is comfortably under 1% of a core.

### 2.6 Concurrency recommendation

Use the sharded-lock design above rather than a single hub actor:
- The actor would serialise every inbound message through one mailbox and force `await`s on the hot path; the lock design does routing on the sender's task and only needs microsecond critical sections.
- Ordering guarantees we need (replay before announcement; response before mode switch; disconnect after unregister) are all *per-connection* and satisfied by the per-connection writer channel, not by global serialisation.
- Rules to enforce in review: `parking_lot::RwLock` (not tokio's), no `.await` while a guard is alive (clippy `await_holding_lock` is on with `-D warnings`), and every hub method returns owned data.

## 6. Risks and mitigations

| Risk | Mitigation |
|---|---|
| ATAK cipher string `DEFAULT:!ECDH` removes all TLS 1.2 ECDHE suites; rustls has no RSA-kx TLS 1.2 suites, so the session must be TLS 1.3 (unaffected by `cipher_list`, needs OpenSSL >= 1.1.1 in commoncommo). | Offer TLS 1.3 + 1.2 (harmless). Test against a real ATAK-CIV at step 13 before building anything on top. Fallback if it fails: feature `stream-openssl` swapping `listener_tls.rs`'s acceptor for `tokio-openssl` on 8089 only (same `CertPrincipalResolver` API). |
| quick-xml fidelity: whitespace text nodes, entities, prefixes. | Tree model keeps order/text/CDATA; drop only whitespace-only text; `unescape_value` handles standard + numeric entities, unknown entities are kept literally; fuzz + proptest; parse failures are per-message drops with metrics, never connection drops. |
| Protobuf detail edge cases (duplicates, malformed numbers, extension details, `how` empty, >64 KiB). | Spec-strict extraction; xmlDetail-wins decode; `extensionDetails` passed through opaquely; oversize substitution with `b-f-t-r`; property tests compare modulo documented losses. |
| Slow or dead consumers back-pressuring the router. | Bounded per-connection queue + `try_send`; consecutive-drop threshold closes the connection; `Arc<EncodedEvent>` sharing keeps memory linear in messages, not recipients. |
| SQLite write throughput / stalls. | Dedicated writer task, batched transactions, WAL, `try_send` with drop counter so the stream path never awaits the DB; history opt-in per type; retention job. |
| Ordering bugs (replay vs announcement, response vs mode switch). | All per-connection ordering goes through one writer channel; `SwitchToProto` carries the response so the flip is atomic with the write; integration test `replay.rs`/`negotiation.rs` assert order. |
| Unknown control types. | Explicit no-op (never delete subscriptions); `t-x-takp-q` outside negotiation is ignored. |
| Time precision mismatch with TAK Server (seconds vs ms). | Keep ms; clients accept both; `CotTime` parser is lenient. |
