# M0-19 — Runtime shutdown and storage hardening

Small, well-scoped fixes surfaced by the e2e harness (M0-14) and the storage review. Read `.claude/plan/status/{M0-14-e2e-specs,M0-12-runtime-bootstrap,M0-07-db-foundation}.md` and `rustak-server/src/{runtime.rs,web/server.rs,db/connection.rs}`, `rustak-core/src/runtime.rs`, `rustak-server/Dockerfile`.

1. **Shutdown budget vs Docker.** actix `shutdown_timeout` is 10 s and h2 keep-alive connections can hold it open, which collides with Docker's default 10 s stop grace. Make the budget configurable (`[server] shutdown_timeout = "8s"` default, validated ≤ 60 s), apply it to the actix servers *and* the stream listener drain, and set `STOPSIGNAL SIGTERM` plus a comment in the Dockerfile explaining that `docker stop -t` must exceed it. Document in `docs/deployment.md`.
2. **Second signal must not skip durability.** Today a second `SIGINT`/`SIGTERM` exits immediately, skipping `Database::close` (WAL truncate + `PRAGMA optimize`). Keep the "second signal ends the wait" behaviour but make it abort the *drain*, then still run `Database::close` with a short hard cap (2 s) before exiting. Add a test in `rustak-core::runtime` for the two-signal sequencing (use a channel-driven fake signal source).
3. **`Database::close` ordering review.** M0-12 reordered `close()` to run `PRAGMA optimize` before `PRAGMA wal_checkpoint(TRUNCATE)`. Confirm that is right (optimize may write; the truncate must come last), make sure the read-only pool is drained before the writer checkpoints (otherwise TRUNCATE is silently downgraded), and add a test that the WAL file is gone/empty after `close()`.
4. **Playwright double-SIGTERM.** With (2) in place, the e2e launcher's second signal no longer matters; remove any launcher-side work-around M0-14 left in `e2e/scripts/start-server.mjs` if one exists, otherwise leave `e2e/` alone.
