# M9-10 — Make every suite run with a server name a careless implementation would break on

**Why — production finding, 2026-09-22.** For three days every event rustak relayed in production was malformed XML: the flow tag is an attribute named `TAK-Server-<[server] name>` and the installation's name is `SierraSoftworks TAK`, so strict parsers (CloudTAK's sax, ATAK's) dropped every relayed message — feed tracks, EUD positions, chat. The fix (`9c6f6f4`, landing now) sanitises the name and makes the parser refuse invalid XML names, with unit tests. But **no suite would have caught it**: every harness, fixture and interop config uses a one-word server name (`rustak`, `rustak-1`, `rustak-interop`). The cheapest durable guard is to make the ordinary test configuration hostile: a display name with a space and punctuation, everywhere, so the node-tak suite, the CloudTAK compose suite (whose sax parser is the strict one that failed in production), the EUD harness and the in-process fake-EUD suites all exercise it on every run. **Launch only after the flow-tag fix is on `main`.**

**Read first:** `.claude/plan/conventions.md`; commit `9c6f6f4` (what was fixed and its tests); `rustak-server/src/testing/context.rs` (or wherever the in-process test config is built) and `rustak-cot/src/detail/flow_tags.rs`; `interop/shared/src/{launch,bootstrap}.ts` and each suite's config template (`interop/node-tak`, `interop/cloudtak`, `interop/eud`); `e2e/` start script config; `config.example.toml` `[server] name`.

**Deliver.**
1. The default server name in every test and interop configuration becomes `Rustak Test & Co. (näme)` or similar: a space, an ampersand, a parenthesis, a non-ASCII letter — characters that are legal in a display name and illegal or special in an XML name, an HTTP header, a file name or a URL. Find every place the name is interpolated into something with a grammar (XML names and attribute values, the JWT `iss`, certificate subjects/SANs, `Content-Disposition` file names, the `.pref` description, the mission-package manifest, the `tak://` QR, log fields) and make sure each either escapes it or derives a safe form; fix what breaks, with a unit test per fix. Anything that must reject such a name instead (e.g. a certificate CN rule) should do so at `--check` with a `Kind::User` message — record each decision.
2. One explicit end-to-end regression: a fake EUD connected over **protobuf** and one over **XML** both receive an event relayed by a server with the spaced name, and the received XML re-parses under a strict parser (use `quick-xml` in a strict configuration or the crate's own parser now that it refuses bad names); same for the `<events>` documents (`/Marti/api/cot/xml/{uid}/all`, mission `/cot`).
3. The CloudTAK compose suite gains (or you confirm it already has) an assertion that CloudTAK's log contains no `Failed to parse CoT XML` / `Attribute without value` after the run — that log line was the only symptom in production.
4. Docs: `docs/deployment.md` note that `[server] name` is a free-text display name and is safe to contain spaces; `docs/interop.md` one line on the hostile default.
