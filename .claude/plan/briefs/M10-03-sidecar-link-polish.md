# M10-03 — Sidecar link messages that say what happened

Three small defects in `rustak-client`, all seen in the Dublin deployment.

**Read first:** `M10-00-wave-rules.md`; briefs and status for M9-07, M9-11 and M9-14; `rustak-client/src/http.rs`; `rustak-client/src/sidecar/{link_health,event_feed,control_link,config,run}.rs`; `docs/plugins.md` sections on the control link and `--check`.

**Deliver.**
1. **Advice that fits the failure** (`rustak-client/src/http.rs`, the `transport` error path). A plain TCP connect timeout (`tcp connect error: deadline has elapsed`) is reported with an advice block that leads with two truststore/TLS hints, which cannot apply to a connect error. Choose the advice from the class of the error, found by walking the source chain with typed checks where the types allow it: name resolution, TCP connect (refused, timed out, unreachable), TLS (certificate, handshake), HTTP status, body/decoding. Each class gets advice an operator can act on; the truststore hints appear only for TLS. Unit-test each class with a constructed error chain; where a real failure is cheap and deterministic to produce (a refused loopback port, a TLS server with an untrusted certificate) test that too.
2. **The counted-reopen warning must not fire for an outage** (`sidecar/link_health.rs` `Reopenings`, used by `sidecar/event_feed.rs`). Seen at 08:06:50Z on 2026-09-22 while rustak was being redeployed: `The server-event feed has closed and reopened 6 times in the last 5m00s; something between this sidecar and [server] control is cutting it.` A server restart is an outage `link_health` already reports. `Reopenings` counts only closes of a feed that had been open and healthy while the control link was up — not failed opens, not closes that coincide with the control link (or the feed's own transport) being down — and its window resets when the link recovers from an outage. The warning keeps its meaning: an intermediary cutting an otherwise healthy feed. Tests on an injected clock: six failed reopenings during an outage produce no such warning and one outage notice; six closes of a healthy feed inside the window still produce it, once.
3. **`--check` validates `[service] control_truststore`** where `truststore` is validated today: a path that does not exist, cannot be read, or holds no certificates is refused at check time with the key named and advice, instead of being discovered at the first control call. Test each of the three.
4. **Docs.** `docs/plugins.md` where `--check` and the control-link messages are described, if the text no longer matches.

The first-connect wording (`Could not connect to the TAK stream yet; retrying.`) landed with M9-15; confirm it in `stream/reconnect.rs` and say so in your status note — do not edit that file.
