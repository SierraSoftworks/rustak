# M9-07 — A sidecar must trust each endpoint with the right roots (first live run: the control link dies after enrolment)

**Why — a production finding, 2026-09-21.** The first real deployment (Nomad, Dublin ADS-B plugin) enrolled perfectly with its workload identity and connected to the CoT stream, then every control-API call failed forever: `/oauth/token` (the jwt-bearer exchange), `/api/v1/events`, `/services/register`, `/services/adsb/heartbeat` — "error sending request", and rustak logged no request at all, so it died in the client's TLS handshake. Cause: `rustak-client/src/http.rs::client` builds **one** client with `tls_certs_only(roots(truststore))` — "the truststore replaces the platform's roots" — and enrolment has just written `<pki_dir>/truststore.pem` = rustak's CA. That is right for the stream and the Marti mTLS listener (internal-CA server certificates) and wrong for `[server] control`, the public listener, which in that deployment presents a Let's Encrypt certificate (`files` mode; `acme` mode is the same). Enrolment itself only worked because no truststore existed yet, so platform roots were in use. `internal` mode hides the bug, which is why every suite passes. The Services page therefore shows nothing for a deployed plugin, which is the thing the maintainer asked for.

**Read first:** `.claude/plan/conventions.md`; `rustak-client/src/http.rs` (the module doc argues for "replace, don't join" — keep that argument where it still applies and rewrite it where it does not), its callers: `enroll.rs:227`, `marti/client.rs`, `control/mod.rs`, `sidecar/mod.rs:205`, `sidecar/{enrolment,workload,control_link}.rs`; status M9-05 and M9-06; `plan.md` → Listeners table (which listener presents which certificate: public = ACME / files / internal CA; Marti mTLS and stream = internal CA always); `rustak-server/src/auth/resolve.rs:115` (`#[instrument("auth.resolve.bearer", skip_all, err(Debug))]`).

**Deliver.**
1. **Trust per endpoint, decided in one place.** A small policy type in `http.rs` (e.g. `Trust::{Internal, Public}`) and the client built per policy:
   - `Internal` — the CoT stream, `[server] marti`: the truststore **replaces** the platform's roots exactly as today (no truststore → platform roots, as today).
   - `Public` — `[server] control` (registration, heartbeat, config, SSE events, the workload token exchange) and enrolment when its target is the control URL: the platform's roots **plus** the truststore's certificates (`add_root_certificate`), so the listener may present a publicly trusted certificate (ACME, files) or an internal-CA one. A new optional `[service] control_truststore = "<pem>"` **replaces** that set for an operator who wants to pin the public listener; document when to use it.
   - Enrolment against `[server] marti` uses `Internal`; against `[server] control`, `Public`.
   Every call site picks its policy explicitly; no default that can be got wrong silently. The stream's own TLS connector (`stream/tls.rs`) is not `http.rs` — confirm it already uses the truststore-replaces rule and leave it alone.
2. **Say what failed.** `http::transport` (and whichever path produced "Could not exchange this workload identity for a token: error sending request for url (…)") must render the error's source chain, so the operator reads `invalid peer certificate: UnknownIssuer` (or a DNS / connect error) instead of reqwest's generic wrapper; keep the existing advice and add one line for the TLS case naming `[service] control_truststore` and the per-endpoint rule. Never include a token or header in the rendered chain.
3. **Server log noise.** On a successful workload enrolment rustak logged `ERROR auth.resolve.bearer: error=Rejected` just before accepting the same request, because a bearer that is not one of rustak's own tokens is tried first and `err(Debug)` logs at ERROR. By design (design 04 D2) a bearer that is not ours is *not an identity*, not a failure: demote that instrumented error to `debug` (tracing's `err(level = …)`), and check the sibling `auth.resolve.*` spans for the same mistake. No behaviour change.
4. **Tests.** Unit: the policy → builder decision for each call site (a pure function you can assert on), including `control_truststore` replacing, and the rendered error chain for a TLS failure (wiremock/rustls test server presenting a certificate the client does not trust → the message contains the rustls reason). Integration (`rustak-server/tests/sidecar_enrolment.rs` or a new file): a server whose **public** listener presents a certificate from a second test CA ("public") while the stream/Marti use the internal CA, the sidecar given `control_truststore` = the public test CA (the platform roots cannot be altered in a test, and `std::env::set_var` is unsafe under `unsafe_code = "forbid"` — so the platform-roots half is proven by the unit test on the policy and by the deployment; say so in the status note): enrol → truststore written → stream connects → **register, heartbeat and the events feed all succeed**, and the same set-up *without* the fix's policy (a truststore-only client against the public listener) is shown to fail, so the test would have caught this. If the in-process harness cannot give the two listeners different certificates cheaply, record exactly what it would take and cover as much as the harness allows.
5. **Docs.** `docs/plugins.md` (credentials/truststore section: the per-endpoint rule in a three-row table; `control_truststore`), the three plugins' `config.example.toml` (`control_truststore` documented beside `truststore`, and `truststore`'s comment corrected to say which endpoints it governs), `docs/deployment.md` "The sidecar images" / "Workload identity" (one paragraph: a public listener with a publicly trusted certificate needs nothing; a private PKI for the public listener needs `control_truststore`).
