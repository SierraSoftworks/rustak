# M9-01 — `rustak-plugin-ais`: ships on the map from open AIS sources

**Why.** The maintainer wants vessel traffic from AIS on the map, from free/open sources. M9-00 built the shared half (`rustak_client::feed`: `Track`, `TrackKind::Vessel`, `Area`, `FeedPublisher`, the `Replay` source, the in-process harness); this brief adds the real sources and the AIS-specific mapping.

**Read first:** `.claude/plan/conventions.md`; status **M9-00** (the `feed` public API you code against — do not redesign it; additive changes to `rustak-client/src/feed/**` are allowed only if a source genuinely cannot be expressed, and must be recorded); `rustak-plugin-ais/**` as M9-00 left it; `docs/plugins.md` "Feed sidecars"; `rustak-server/tests/feed_sidecars.rs` (the harness helper).

**Sources (facts verified by the orchestrator on 2026-09-20; re-check the live docs before relying on a detail not listed here):**
1. **AISStream.io** — `wss://stream.aisstream.io/v0/stream`. Free API key from the site's `/account` page (shown once). Within 3 s of connecting send one JSON subscription: `{"APIKey": "...", "BoundingBoxes": [[[lat1, lon1], [lat2, lon2]], ...], "FiltersShipMMSI": ["...", …] (optional, ≤200), "FilterMessageTypes": ["PositionReport", "ShipStaticData", "StandardClassBPositionReport", "ExtendedClassBPositionReport"] (optional)}` — **latitude first** in each pair. Messages: `{"MessageType": "PositionReport", "MetaData": {"MMSI": 244660000, "ShipName": "…", "latitude": …, "longitude": …, "time_utc": "…"}, "Message": {"PositionReport": {"Cog": …, "Sog": …, "TrueHeading": …, "NavigationalStatus": …, "Latitude": …, "Longitude": …, "Valid": true, …}}}`; `ShipStaticData` carries `Name`, `CallSign`, `ImoNumber`, `Type` (the AIS ship-type code), `Destination`, `Eta`, `Dimension`; the class-B position reports carry `Sog`/`Cog`/`TrueHeading` without a navigational status. Limits: 3 connections per account and per IP; keep reading or the server drops you; enable `permessage-deflate`; reconnect with backoff. Heading 511 and COG 360 mean "not available"; SOG 102.3 means "not available". The site publishes no licence text — document it as "free API key, terms on aisstream.io".
2. **Local receiver over UDP** — NMEA 0183 `!AIVDM,…` sentences (multi-fragment) as emitted by AIS-catcher, rtl_ais or a dAISy hat, one or more sentences per datagram. Decode with the `nmea-parser` crate (0.11, Apache-2.0; `NmeaParser::parse_sentence`, `ParsedMessage::{VesselDynamicData, VesselStaticData}` with `mmsi`, `latitude`, `longitude`, `sog_knots`, `cog`, `heading_true`, `nav_status`, `ship_type`, `name`, `call_sign`, `imo_number`, `destination`; it keeps multi-fragment state between calls). No key, no terms — the receiver is the operator's own.
3. **Fintraffic Digitraffic (Finland)** — optional third source, no key: MQTT over WebSocket `wss://meri.digitraffic.fi:443/mqtt`, topics `vessels-v2/<mmsi>/locations` and `vessels-v2/<mmsi>/metadata` (`vessels-v2/#` for all); location JSON `{time, sog, cog, navStat, heading, lon, lat, posAcc, raim, rot}`, metadata `{timestamp, name, callSign, imo, type, destination, eta, draught, …}`; send a `Digitraffic-User: rustak-plugin-ais/<version>` header; licence CC BY 4.0 (state it). Implement it only if an MQTT-over-WebSocket client is cheap (`rumqttc` with websocket feature, current stable) — otherwise leave a documented stub and say so; the first two sources are the deliverable.

**Deliver.**
1. `Source` enum gains `AisStream { api_key, message_types? }`, `Udp { listen: SocketAddr }`, and (optional) `Digitraffic {}`; `Replay` stays. Each source is one file under `src/sources/`, yields `Track`s into the `FeedPublisher`, reconnects with capped exponential backoff and logs state changes at `info`, never logs the API key (redacting `Debug`).
2. **Mapping** (`src/mapping.rs`, unit-tested): `id = "AIS-<mmsi>"`; `TrackKind::Vessel(class)` from the ship-type code — 30 → Fishing; 36, 37 → Leisure; 55 → LawEnforcement; 35 → Military; 60–89 (passenger, cargo, tanker) → Merchant; everything else/unknown → Other; `callsign` = ship name when known else `MMSI <n>`; speed knots → m/s; course from COG, heading from true heading, "not available" sentinels → `None`; `remarks` lines: `MMSI`, `Call sign`, `IMO`, `Type` (code and word), `Status` (nav status word), `Destination`, `ETA`, `Length/Beam` when dimensions are known, `Source`. Static data arrives separately from positions: keep a per-MMSI static cache (bounded, evicted with the publisher's expiry) and re-offer the track with enriched remarks/callsign when static data arrives after a position.
3. **Config** (`config.example.toml`, `deny_unknown_fields`, every key with its default): the M9-00 `Settings` plus the sources; an `[settings.source]` example for each. Defaults: `publish.stale = "10m"` for anchored/moored vessels and `"2m"` otherwise (choose per navigational status; document), `min_interval = "5s"`, `max_interval = "3m"`, `min_move_m = 25`.
4. **Tests**: unit tests for every mapping arm and sentinel; decoder tests for the UDP source using **sentences you encode yourself** with the crate's or your own encoder (no copied captures) covering a class-A position, a class-B position, a two-fragment type-5 static message and a malformed line; an AISStream parser test on a hand-written JSON sample of each message type; an end-to-end test through the M9-00 harness with the UDP source fed from a test socket, asserting the CoT type, callsign and `<track>` on a fake EUD; a throttling assertion.
5. **Observability for the Services view (added 2026-09-20).** Report the `FeedCounters` (offered, published, suppressed, expired), the tracked-count, the active source kind and its connection state (connected / reconnecting since / last error, credentials redacted) in the sidecar's heartbeat status through whatever `SidecarContext`/control-link surface M6-01 gives for "saying more than healthy" (see `docs/plugins.md` → Registering with the server → Saying more than "healthy"), so an administrator can monitor the plugin from the admin UI's Services page without reading logs. Mark the service `degraded` when the source has been reconnecting for longer than two poll intervals and `unhealthy` when it has never connected. If the SDK's per-service config KV can be read cheaply at start-up, honour a documented `area` override from it (server-side configuration wins over the file, logged at `info`); if not, say so in the status note rather than building it.
6. **Docs**: `rustak-plugin-ais/README.md` (what it does, each source with how to obtain access, the data terms, the CoT mapping table, example config, running it in Docker beside rustak); `docs/plugins.md` cross-link; `README.md` — turn "in progress" into a sentence.
