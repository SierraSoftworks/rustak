# M1-07 — Wire the sidecar harness to the real stream client

**Context.** M0-15 built `rustak-client::sidecar` (the `Sidecar` trait, `run(config)` harness, `SidecarEvent`) before the stream client existed, so `SidecarEvent::Cot` carries a raw `Box<rustak_cot::proto::TakMessage>` and the harness has no real connection loop. M1-04/M1-04b since delivered `rustak_client::stream` (`StreamConfig`, `connect`, `TakStream` implementing `Stream<Item = Result<Event,_>> + Sink<Event>`, `Reconnecting` with backoff + `ConnectHook`, `tls::TlsIdentity`, `Endpoint`). Read `.claude/plan/status/{M0-15-plugin-example,M1-04-client-stream,M1-04b-client-stream-fixups}.md`, `.claude/plan/compat/streaming.md`, `docs/plugins.md`, and the current `rustak-client/src/{sidecar,stream}/**`, `rustak-plugin-example/src/main.rs`.

**Deliver.**
1. `SidecarEvent::Cot(Box<rustak_cot::Event>)` — the parsed CoT event model, not the protobuf. Keep `Connected { endpoint }` / `Disconnected { reason }`; add `Negotiated { protobuf: bool }` if the harness can observe it cheaply (drop it otherwise). Enum stays `#[non_exhaustive]`.
2. The harness (`sidecar/run.rs`) drives a `Reconnecting` stream built from the sidecar config (endpoint, uid `SERVICE-<name>`, callsign, TLS identity from the configured cert/key/truststore files — reuse `sidecar::config`'s existing fields; do not invent enrollment here, that is M6's `enroll.rs`), forwarding inbound events to `Sidecar::on_event`, sending whatever `on_event`/`tick` returns (the existing `Vec<Event>`/publish shape — keep the trait's public surface unless it has to change to hold `rustak_cot::Event`; document any change in the status file and in `docs/plugins.md`), calling `tick` on the configured interval, and stopping on `Shutdown`. Control messages (ping/pong, takp) stay inside `TakStream`; the plugin never sees them.
3. `rustak-plugin-example` publishes its heartbeat as a real `rustak_cot::Event` (type `a-f-G-U-C`-style SA with `<contact callsign>` and `<__group>` so it shows up as a contact) and logs received events' `uid`/`type`. It must still compile and run with `cargo run -p rustak-plugin-example -- --config rustak-plugin-example/config.example.toml --check` (or whatever the existing check flag is).
4. Tests: a harness test against `rustak_client::stream::testing::Eud`-style in-memory duplex (behind the crate's `testing` feature) proving: connect → `Connected` → an inbound event reaches `on_event` as `Event` → `tick` output is written to the wire → the wire dropping yields `Disconnected` then a reconnect attempt. Keep tests deterministic (paused tokio time).
