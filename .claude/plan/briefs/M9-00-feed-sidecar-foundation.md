# M9-00 — Foundation for information-feed sidecars (AIS and ADS-B follow in M9-01/M9-02)

**Why.** The maintainer wants rustak plugins that put open-data feeds on the map: ships from AIS and aircraft from ADS-B, using free/open sources. Both are the same shape — poll or subscribe to a source, turn each observation into a CoT track, publish it on a channel at a sane rate, let it go stale — so the shared half is built once here, in `rustak-client`, and the two source-specific plugins are then written in parallel against it. This brief delivers no real data source; it delivers the model, the publisher, two runnable skeleton crates wired into CI and Docker, and the end-to-end test harness the plugin briefs will use.

**Read first:** `.claude/plan/conventions.md`; `plan.md` → "Plugin (sidecar) contract" and the `rustak-client` layout; `docs/plugins.md` (the recipe the skeletons must follow); `rustak-plugin-example/**` (Cargo.toml, Dockerfile, config.example.toml, main.rs — the template); `rustak-client/src/sidecar/**` (`Sidecar`, `SidecarContext`, `run`/`run_with`, `SidecarConfig<S>`); `rustak-cot/src/{event,detail/*,types}.rs` (the `EventBuilder`, `Contact`, `Track` typed details); status M6-01 (how `rustak-server/tests/services_flow.rs` runs a sidecar in-process against a real server and a fake EUD — that is your harness template) and M1-07; `.github/workflows/rust.yml` lines ~450, ~700, ~795 (the three matrices that enumerate binary crates) and `docs/ci.md`; `docs/deployment.md` (the plugin images section, if any).

**What the two plugins will need from you (facts, so the model fits):**
- *AIS* observations carry: MMSI (the stable id), ship name, call sign, IMO, AIS ship-type code (0–99: 30 fishing, 35 military ops, 36 sailing, 37 pleasure, 50 pilot, 51 SAR, 52 tug, 55 law enforcement, 60–69 passenger, 70–79 cargo, 80–89 tanker), navigational status (0 under way, 1 at anchor, 5 moored…), lat/lon, SOG in knots, COG and true heading in degrees, destination, ETA, dimensions, an observation time. Sources: a WebSocket JSON stream (AISStream.io, bounding-box subscription), NMEA 0183 `!AIVDM` sentences over UDP from a local receiver, and JSON over HTTP. Position reports arrive every 2–10 s per moving vessel, every 3 min at anchor.
- *ADS-B* observations carry: ICAO 24-bit hex (the stable id), flight/callsign, registration, aircraft type code, emitter category (A1–A7 aeroplanes by weight class with A7 = rotorcraft, B1 glider, B2 lighter-than-air, B4 ultralight, B6 UAV, B7 space, C1–C3 surface vehicles), lat/lon, barometric altitude and geometric (WGS-84) altitude in feet, ground speed in knots, track in degrees, vertical rate, squawk, on-ground flag, seconds since last position. Sources: a readsb/dump1090 `aircraft.json` (local file or HTTP), the same shape from public aggregators (`adsb.lol`, `adsb.fi`, `airplanes.live` — `v2/point/{lat}/{lon}/{radius_nm}`), and OpenSky's `states/all?lamin&lomin&lamax&lomax` with OAuth2 client credentials. Updates every 1–10 s per aircraft; a busy 250 nm circle holds a few hundred aircraft.
- Both need an **area of interest** (a bounding box or a centre + radius) that the source subscribes with *and* the publisher filters on, and both need publishing throttled per track so a thousand ships do not become a thousand CoT messages a second.

**Deliver.**
1. **`rustak_client::feed`** (new module, several files): 
   - `Track`: `id: String` (already prefixed, e.g. `AIS-244660000`, `ADSB-3c6444`), `kind: TrackKind`, `position: (f64, f64)`, `altitude_hae_m: Option<f64>`, `speed_mps: Option<f64>`, `course_deg: Option<f64>`, `heading_deg: Option<f64>`, `callsign: Option<String>` (what the map shows), `remarks: Vec<(String, String)>` (ordered key/value lines rendered into `<remarks>`), `observed_at: DateTime<Utc>`, `on_ground: bool`.
   - `TrackKind` and the CoT type mapping, written from the public MIL-STD-2525 symbol hierarchy CoT types follow (`a-<affiliation>-<battle dimension>-…`): `Vessel(VesselClass)` with `Merchant → S-X-M`, `Fishing → S-X-F`, `Leisure → S-X-R`, `LawEnforcement → S-X-L`, `Military → S-C`, `Other → S-X`; `Aircraft(AircraftClass)` with `CivilFixedWing → A-C-F`, `CivilRotary → A-C-H`, `LighterThanAir → A-C-L`, `MilitaryFixedWing → A-M-F`, `Uav → A-M-F-Q`, `Unknown → A`; `GroundVehicle → G-E-V-C`. Affiliation is a parameter (`Affiliation::{Unknown, Friend, Neutral, Hostile, Pending}` → `u f n h p`), default `Unknown`. Provide `TrackKind::cot_type(affiliation) -> String` and unit tests on every arm. Do **not** consult ATAK's or TAK Server's type tables (GPL); the 2525 hierarchy is public and the arms above are the contract.
   - `Track::to_event(&self, affiliation, stale: Duration) -> rustak_cot::Event`: `uid = id`, `type` as above, `how = "m-g"`, point from position with `hae` from altitude (else 9999999.0), `ce`/`le` 9999999.0, `time = observed_at`, `start = time`, `stale = time + stale`; `<contact callsign="…"/>` when a callsign exists (no endpoint — it is not a chat peer); `<track speed course/>` when known (speed in m/s as CoT expects, course in degrees); `<remarks>` as `key: value` lines joined by newlines. Golden test on the XML bytes.
   - `Area`: `Bbox { south, west, north, east }` (anti-meridian aware) and `Circle { lat, lon, radius_km }`, `contains(lat, lon)`, `bbox()` (a circle's enclosing box, for sources that only take boxes), `radius_nm()` helpers, serde with `deny_unknown_fields` so plugins embed it in their settings.
   - `FeedPublisher`: takes the sidecar's stream handle (whatever `SidecarContext` exposes for sending CoT — read `services_flow.rs`/the example) and `PublishPolicy { stale: Duration, min_interval: Duration, max_interval: Duration, min_move_m: f64, max_tracks: usize }`; `offer(track)` publishes when the track is new, when it moved ≥ `min_move_m` or changed course/speed materially, or when `max_interval` elapsed since its last publish, never more often than `min_interval` per track; `tick()` drops tracks unseen for longer than `stale` (no delete message — TAK clients expire by `stale`) and evicts the oldest beyond `max_tracks`; counters (offered, published, suppressed, expired) exposed for the plugin's heartbeat status and logged at `info` on a slow cadence. Deterministic unit tests with a fake sink and a controllable clock.
   - A `Feed` trait (or plain function shape — choose what keeps plugins small): an async source yielding `Track`s into the publisher, with reconnect/backoff left to the source.
2. **Two skeleton crates**: `rustak-plugin-ais` and `rustak-plugin-adsb`, copied from the example per `docs/plugins.md`: `Cargo.toml`, `Dockerfile`, `config.example.toml`, `README.md` (purpose, data sources *to come*, licensing placeholder), `src/main.rs` + `src/lib.rs` (so the integration harness can drive them as a library), `Settings { area: Area, publish: PublishPolicy (with defaults: stale 2 min for AIS / 90 s for ADS-B, min_interval 5 s, max_interval 60 s, min_move_m 25, max_tracks 5000), affiliation, source: Source }` where `Source` is a `#[serde(tag = "kind")]` enum containing only `Replay { path }` for now — a source that reads a newline-delimited JSON file of `Track`s (our own fixture format) and offers them on a timer, which is what the harness and the demo use. Each compiles, `--check`s its example config, runs, registers, publishes the replay file, and stops cleanly.
3. **CI and Docker**: add both crates to the three matrices in `rust.yml` (build, docker-build, docker-publish) exactly as `rustak-plugin-example` appears, producing `ghcr.io/sierrasoftworks/rustak-plugin-ais` and `…-adsb`; the CI steward has been told you are editing those three matrix blocks and nothing else in `.github/`. `docs/ci.md` matrix description; `docs/deployment.md` gets the two images listed where plugin images are documented.
4. **Test harness**: `rustak-server/tests/feed_sidecars.rs` (feature `testing`): starts an in-process server, enrols a service identity for the plugin (the way `services_flow.rs` does), runs each skeleton plugin as a library with the `Replay` source over a fixture of five tracks, connects a fake EUD on a channel the service can publish to, and asserts the five CoT events arrive with the expected uids, types, callsigns and `<track>`; a second case proves throttling (a replay that repeats one track ten times in a second yields one publish). Keep the harness reusable: a helper the M9-01/M9-02 tests can call with a different `Source`.
5. **Docs**: `docs/plugins.md` gains a "Feed sidecars" section (the `feed` module, the `Track` contract, the policy knobs, the replay fixture format); the two READMEs; `README.md` one line under the sidecar highlight naming the two plugins as in progress.
