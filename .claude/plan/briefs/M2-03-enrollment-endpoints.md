# M2-03 — Enrollment endpoints, `/oauth/token`, Marti mTLS listener and principal resolution

**Goal:** make ATAK and CloudTAK able to enrol and authenticate. Deliver, per `compat/enrollment.md`, `compat/oauth.md`, `compat/cloudtak.md` and design 03 §5–§7:
1. `rustak-server/src/auth/resolve.rs` (extend M0-11's bearer-only resolver): `ListenerAuthPolicy {cert, bearer, basic: Off|EnrollmentOnly|All}` and `resolve_principal(req, policy)` in order cert (`PeerCertificate` from `req.conn_data()`, CN → `Username`, fingerprint → `certificates` row: must exist, not revoked, user matches, user not disabled; `touch_last_seen`; device from the cert row; groups via `identity::members::effective_for_device`) → bearer (our JWT; jti not revoked; user enabled) → Basic (only on `/Marti/api/tls/**` and `/oauth/token`; `identity::verify` with `Purpose::Enrollment`/`Purpose::OAuthPassword`; rate limited) → else 401 with the correct body per path (`/oauth/token` → `{"error":"invalid_grant","error_description":"Bad credentials"}` 401; `/Marti/**` → plain `Unauthorized` + `WWW-Authenticate: Basic realm="rustak"` only where Basic is allowed). `D2` rule from design 04 §0: a bearer that is not our RS256 JWT is never treated as identity (mission tokens come later).
2. `marti/tls.rs`: `GET /Marti/api/tls/config` (exact `ns2:certificateConfig` XML with ≥2 `nameEntry`, `Content-Type: application/xml`), `POST /Marti/api/tls/signClient/v2?clientUid=&version=` (Accept dispatch: JSON `{signedCert, ca0, ca1…}` bare base64 64-col vs `application/xml` `<enrollment><signedCert/><ca/>…</enrollment>`; else 400; body PEM/bare/DER via `pki::csr`; CN must equal the authenticated user; issue via `Pki` with `channels_marker` when `version` present; persist with `issued_via`, `client_uid`, `credential_id`; device `upsert_seen(clientUid)`; consume a one-time enrollment token **only on success**; audit), `POST /Marti/api/tls/signClient` (legacy PKCS#12), `GET /Marti/api/tls/profile/enrollment?clientUid=` → 204 (profiles arrive in M3), `GET /Marti/api/device/profile/connection` → 204.
3. `marti/oauth.rs`: `POST /oauth/token` (`grant_type=password` with `username`/`password` → `identity::verify(Purpose::OAuthPassword)` (client passwords only) → `JwtIssuer::issue` → `200 {"access_token","token_type":"Bearer","expires_in"}` exact `application/json`; `refresh_token` grant via M0-11's refresh tokens; other grants → 400 `unsupported_grant_type`; missing fields → 400 `invalid_request`; rate limited), `GET /oauth/token_key`, `GET /oauth/jwks`.
4. Marti mTLS listener: `web/server.rs::build_marti(ctx)` bound to `[web.marti].listen` with `pki::tls::marti_server_config` (client cert **required**) and `on_connect(peer::on_connect_capture)`, serving the full `marti` scope + `/files/api/config`; the public listener also serves the `marti` scope with the public policy (bearer + Basic on enrollment/oauth paths). Spawn it from `runtime.rs` (small edit next to the web/stream spawns).
5. Integration tests (`rustak-server/tests/enroll_*.rs`, feature `testing`): node-tak-shaped JSON enrolment (Bearer `tls/config`, Basic `signClient/v2` with PEM CSR, `Accept: application/json`) → reconstruct PEM → reqwest mTLS `GET /Marti/api/version` on the Marti port → 200 text; ATAK-shaped XML enrolment with a one-time token (`Accept: application/xml`, `Content-Type: application/octet-stream`, bare base64 body) → `<enrollment>` with ≥1 `<ca>`; second use of the token → 401; CN spoof → 403; legacy v1 → parseable PKCS#12; revoke → mTLS handshake fails; `/oauth/token` happy path + `invalid_grant` + rate limit 429; `Content-Type` exactness on every JSON response.
