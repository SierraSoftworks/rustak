# M7-01 — Bind `[web.public] plain_bind`, make the ACME statics ordinary handles, refuse wildcards at `--check`

**Why.** Three ACME loose ends from M2-10 (`.claude/plan/backlog.md`): `plain_bind` is parsed and validated but never bound, so an `http-01` deployment behind a port-80 proxy has nothing to forward to and the `80 → 443` redirect design 03 §3 describes does not exist; the certificate resolver (`pki/acme/mod.rs:54`) and the `http-01` token map (`pki/acme/challenge.rs:42`) are process-wide statics because `services/mod.rs` had no slot for them; and a wildcard name passes `--check` although no challenge rustak implements can validate one (`dns-01` only).

**Read first:** `.claude/plan/conventions.md`; `plan.md` → Listeners and the TLS row of "Design artefacts"; `design/03-identity-pki-acme-auth.md` §3 (ACME, the plaintext listener and redirect); status M2-10 (ACME implementation and the notes that became these backlog lines), M2-13 (TLS files reload — how `web/server.rs`/`runtime.rs` build and hot-swap listeners today); `config/acme.rs`, `config/validate.rs` (the `Http01` arm at ~line 206 and `plain_bind` collision check at ~368), `config/web.rs:79`, `web/{mod,server}.rs`, `runtime.rs`, `services/mod.rs` (look for an existing `Late<...>` pattern or the closest equivalent), `pki/acme/{mod,challenge,order}.rs`.

**Deliver.**
1. **Plaintext listener.** When `[web.public] plain_bind` is set, bind it as an HTTP (no TLS) actix server that serves exactly two things: the `http-01` challenge routes (`/.well-known/acme-challenge/{token}` via `pki::acme::http01_routes` or its equivalent) and a `301` to `https://<host><path>` for everything else. The `Location` host is the request `Host` header (validated against `[server] domains`, else the canonical host) and the port is the first public TLS listener's port when it is not 443. No API, no UI, no Marti, no cookies on this listener; unmatched non-GET → `301` too (a redirect is harmless and keeps the surface one line). This is not an `allow_insecure_http` listener and must not be gated by it; document the distinction in `config.example.toml` beside `plain_bind` and in `docs/deployment.md` (ACME section: `http-01` on `:80` directly, or `plain_bind = ":8080"` behind a proxy).
2. **Handles, not statics.** Give `services/mod.rs` a slot for the ACME state (the resolver and the token map) initialised once by the runtime; thread it to the challenge routes and the TLS acceptor builders; delete `RESOLVER` and `TOKENS`. Keep the doc comment in `challenge.rs` that explains the design, rewritten for the handle. Tests that relied on the statics use the handle.
3. **Wildcards.** `--check` (config validation) refuses a `*.` name under `[acme]` with a `Kind::User` error whose advice says `dns-01` is not implemented and to list the concrete hosts instead. Remove or adjust the wildcard-related tests in `config/acme.rs` (~385–406) accordingly; keep the IP/private-network checks.
4. **Tests.** Integration test (`rustak-server/tests/`): a server started with `plain_bind` answers the challenge path with the token body and `301`s `/api/v1/health` to the TLS origin with the right host and port; a request with a foreign `Host` header is redirected to the canonical host, never echoed. Unit tests for the validation rule. The existing ACME tests keep passing.
5. **Docs**: `docs/deployment.md` ACME section; `config.example.toml`.
