# M7-04 — Run `rustak-ui`'s unit tests in CI; let demo mode show every TLS source

**Why.** `rustak-ui` has ~20 unit tests across 18 files that are type-checked by `cargo clippy --all-targets --target wasm32-unknown-unknown` and never run: a failing assertion is not a failing build (found by M2-14). Separately, `fixtures::certificates::acme_status()` (`rustak-ui/src/fixtures/certificates.rs:189`) is the only demo TLS status, so the `files` rows, note and banner M2-14 added to the Transport security card cannot be seen with `?demo`.

**Read first:** `.claude/plan/conventions.md`; `.github/workflows/rust.yml` `ui` job (lines ~177–250: wasm32 target, `cargo binstall trunk@0.21.14`, clippy, two `trunk build`s) and `docs/ci.md` (the job graph and "reproduce locally" sections — keep both truthful); `rustak-ui/Cargo.toml`; status M2-14 (the TLS card) and M2-07/M3-04 (UI patterns, demo fixtures, the `?demo` macro); `rustak-ui/src/pages/settings_tls.rs`; `e2e/` (how the Playwright suite drives `?demo`).

**Deliver.**
1. **Tests that run.** Pick the cheapest mechanism that makes a deliberately failing assertion fail the `ui` job, and prove it locally by breaking one test, watching it fail, and restoring it (say so in the status note). Options, in order of preference: (a) a host-target `cargo test` for `rustak-ui` — yew and web-sys compile on the host, and tests that never touch the DOM run fine; gate any test that needs a browser behind `#[cfg(target_arch = "wasm32")]` and count how many are excluded; (b) `wasm-bindgen-test` with `wasm-pack test --headless --chrome` or `--node`, if (a) leaves too much behind — cost it against the `ui` job's current ~1.5 min. Add the step to the `ui` job after clippy and before `trunk build`; if it needs a tool, install it the way trunk is installed (binstall, prebuilt only, pinned). Add the command to the "reproduce locally" list in `docs/ci.md` and to the README's Development block if it lists the UI commands.
2. **Demo TLS sources.** Give the fixtures a way to show each TLS source the card renders (`acme` as today, `files` with the reload note and the banner, `internal`), selected by a query flag the demo already understands or a fixture toggle the settings page exposes in demo mode — follow whatever the other pages do for alternate demo states; if nothing exists, the simplest is `?demo&tls=files`. Update the demo/e2e spec so the `files` state is rendered at least once (a screenshot-free assertion on the banner text is enough).
3. **Any test that was silently wrong** now that they run: fix it or delete it, and list each in the status note.
