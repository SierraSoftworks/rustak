# M10-13 — One `SourceState` for the feed plugins

**Why.** Four feed plugins poll an upstream over HTTP and each carries its own copy of the same machinery: ADS-B and AIS a `SourceState` with `notice.rs` (log on change of state), ESB and FIRMS their own since M10-04, which copied `notice.rs` again. The backlog said to lift one into `rustak_client::feed` "when a fourth HTTP feed arrives"; there are four. M10-04's status note lists what it found duplicated — start there.

**Read first:** `M10-00-wave-rules.md`; status notes for M10-04 (the duplication list), M10-05 (the refused-rung memory), M9-08 and M9-12; `rustak-plugin-{adsb,ais,esb,firms}/src/sources/` in full; `rustak-client/src/feed/` (`FeedPublisher`, `source.rs`, `policy.rs`) and how its periodic report is timed.

**Deliver.**
1. **Decide what is genuinely shared**, from the code, and write the decision down before moving anything: the state-change notices (outage run, rate-limit run, reminder cadence, recovery), the `Retry-After` parsing (M9-12's tolerant `retry_after()`), "an explicit `poll` is a floor", the periodic counters cadence. ADS-B's adaptive cadence (AIMD, the refused-rung memory) is shared only if a second plugin would use it as it is; otherwise it stays in ADS-B behind the shared type's seam. AIS's WebSocket source is not a poller: share with it only what fits without bending either side.
2. **Lift it into `rustak_client::feed`** as a small, documented, clock-injected module, and move the four plugins onto it. No behaviour changes: every log line's wording, level and cadence, every metric name, and every timing rule stays as it is on main unless two plugins disagree — where they disagree (M10-04 names two: ESB/FIRMS return to the operator's `poll` after a stated delay while ADS-B keeps the floor raised; a configuration document with no `area` gives the choice back to the file in ESB/FIRMS and keeps the current area in ADS-B), do **not** pick a winner silently: keep each plugin's behaviour through a parameter and put the question to the orchestrator in your status note.
3. **Tests move with the code.** The shared module carries the tests of the shared behaviour once; each plugin keeps the tests of what is its own. No assertion is lost: list in the status note which tests moved, merged or stayed. The per-plugin suites and `rustak-server/tests/feed_sidecars.rs` pass unchanged.
4. **`docs/plugins.md`**: a section for plugin authors on the shared source state — what it gives a new HTTP feed for free.

**Files you own:** a new module under `rustak-client/src/feed/`, `rustak-client/src/feed/mod.rs`, `rustak-plugin-{adsb,ais,esb,firms}/src/sources/**` and each plugin's `lib.rs` where it wires the source, `docs/plugins.md` (the new section only), your status note. **Not yours:** `rustak-client/src/sidecar/**`, `rustak-client/src/http*`, `rustak-server/**` (read and run only).
