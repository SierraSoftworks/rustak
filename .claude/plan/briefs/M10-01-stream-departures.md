# M10-01 — A routine departure must not read as an error

**Why — production, Dublin, 2026-09-22.** The first roll with M9-15's leave line showed `A client left the stream. user=adsb … reason=read_error connected_for=91.343820306s` for an operator's routine restart of a sidecar. Two causes and one cosmetic slip:
- The sidecar harness never closes its TAK stream on shutdown: nothing in `rustak-client/src/sidecar/{run,link}.rs` calls `SinkExt::close`, although `TakStream::poll_close` (`rustak-client/src/stream/connection.rs`, and the reconnecting wrapper in `stream/reconnect.rs`) exists and would send the TLS `close_notify`. The socket is dropped and the server's TLS layer reports an unexpected end-of-file.
- The server names every such end-of-file `read_error` (`rustak-server/src/stream/liveness.rs`, set in `stream/connection.rs`). An end-of-file without `close_notify` is also what every phone that loses signal or is killed produces; it is not an error worth the name.
- `connected_for` is a `Duration` rendered with `Debug` (`connection.rs:225`), so it prints nanoseconds.

**Read first:** `M10-00-wave-rules.md`; status and brief for M9-15 (`.claude/plan/{briefs,status}/M9-15-*`); `rustak-server/src/stream/{connection,liveness,metrics}.rs`; `rustak-client/src/sidecar/{run,link}.rs`; `rustak-client/src/stream/{connection,reconnect}.rs`; `docs/deployment.md` where the leave reasons are listed.

**Deliver.**
1. **Harness closes its stream on shutdown.** When the shutdown token fires, the sidecar closes the TAK stream (flush what is queued, then `close`, so `close_notify` is sent), bounded by a short timeout that fits inside the existing `shutdown_grace`; a close that fails or times out is logged at `debug` and does not change the exit code. A stream that is not currently connected is simply dropped.
2. **Server names the cause honestly.** A clean close (`close_notify`, or a TCP FIN at a frame boundary where the TLS layer reports a clean end) stays `client_closed`. An end-of-file without `close_notify` and a connection reset become a cause of their own — `client_vanished` — counted separately in `StreamMetrics`. `read_error` remains for what is genuinely an error (malformed framing, a TLS alert, an I/O error that is not an end-of-file or reset). Classify from the error's kind/source chain, not from message text where a typed route exists; enumerate the mapping in the rustdoc.
3. **`connected_for` is a number of seconds with one decimal** (`91.3`), logged as a number so it can be graphed; nanoseconds go.
4. **Tests.** A harness test that starts a sidecar against an in-process server, stops it through its shutdown token, and reads the server's per-reason counter: `client_closed` went up by one and `client_vanished`/`read_error` did not. A server test that drops a client socket without closing and reads `client_vanished`. Unit tests for the classification. No wall-clock upper bounds.
5. **Docs.** Update the list of leave reasons wherever it is documented (`docs/deployment.md`, and `docs/plugins.md` if it says what the harness does on shutdown).
