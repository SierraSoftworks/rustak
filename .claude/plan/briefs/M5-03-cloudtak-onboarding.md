# M5-03 — "Onboard CloudTAK": one action that produces everything CloudTAK's server setup needs

**Why.** CloudTAK's *Configure Server* page will not save without an administrator client certificate uploaded as a `.p12` plus a username and password; today the only way to get that `.p12` from rustak is a manual `openssl` CSR → `signClient/v2` → `pkcs12 -export -legacy` recipe, because rustak never holds a client's private key (`POST /api/v1/config-packages` refuses `include_client_cert`). Requested by the maintainer via the cluster deployment.

**Design (the one deliberate exception to "rustak never keeps a device's private key"):** operator-initiated, admin-only, audited, one-shot, and the key never touches the database unsealed or outlives the hand-over.

**Read first:** `.claude/plan/conventions.md`; `plan.md` → Identity & auth model; `compat/cloudtak.md` (CloudTAK's server setup: `url=ssl://host:8089`, `api=https://host:8443`, `webtak=https://host:8446`, the first `PATCH /api/server` needs certificate **and** username/password — see M4-03's correction in that file); status M2-01 (`pki::issue`, `pki::p12::client_keystore`, `p12_legacy` → 3DES/RC2 + SHA-1 MAC, which `@tak-ps/node-p12` requires), M2-02 (`ClientPassword` minting), M2-08 (`/api/v1/certificates`), M3-02 (`web/api/config_packages.rs` — the refusal you are carving an exception next to), M2-07/M3-04 (UI patterns: `secret_reveal`, `confirm`, download helper), M4-03 (`interop/cloudtak` runner — it enrols by hand today).

**Deliver.**
1. **Server** `POST /api/v1/users/{username}/cloudtak-onboarding` (admin): body `{ credential: "mint" | { existing: <id> }, label?, host?, ports?: { stream, marti, public } }`. In one transaction-ish flow: mint a `ClientPassword` (label defaulting to "CloudTAK", purpose marked) or verify the referenced one belongs to the account; generate an RSA-2048 key pair **in memory** (`spawn_blocking`); issue a certificate through the normal `pki::issue` path with `CN=<username>` and the configured name entries, recorded like any other client certificate but with `kind`/label `cloudtak` so `/api/v1/certificates` lists it and `POST /certificates/{id}/revoke` ends it; build the legacy PKCS#12 (`pki::p12::client_keystore` with `legacy = true`, chain included, a generated 16-char passphrase); stash the bundle **sealed** (AES-GCM via the existing `Sealed`, in the KV store with a 10-minute TTL) under a random one-shot download id; return `{ username, password (shown once), p12_download_url, p12_password, urls: { stream, api, webtak }, certificate_id, credential_id, expires_at }`. `GET /api/v1/cloudtak-onboarding/{id}.p12` (admin, same session) streams the bundle **once** and deletes it; a second fetch is `410`; expiry sweeps it. Audit `cloudtak.onboarding.created` (account, credential id, certificate id, requesting admin) and `cloudtak.onboarding.downloaded`. Never log the key, the passphrase or the password.
2. **URLs**: default to the canonical host (`[marti] public_host` → `[server] base_url` → first domain) and the configured listener ports; the body may override host and each port (the deployment here needs host ports `28089/28443/28446`); validate and echo them back.
3. **UI** (`rustak-ui`): an **Onboard CloudTAK** action on the user detail page (and, from the Users page, a small "Create CloudTAK account" flow that creates a service-kind account first) → a result page showing the three URLs, username and password with copy buttons (secret shown once), the `.p12` download button (one-shot, with its passphrase), an optional advanced section to override host/ports before generating, and a plain sentence stating the exception (the key was generated on the server for this download and discarded). Demo fixtures; Playwright spec for the happy path and the second-download `410`.
4. **Tests**: server — authz matrix, mint-vs-existing, PKCS#12 parses with legacy algorithms and the key matches the certificate (use `p12-keystore`/`openssl`-free parsing available in the tree), one-shot semantics, expiry sweep, audit rows, revocation of the issued certificate works; **interop** — add a scenario to `interop/cloudtak` (and, if cheap, `node-tak`) that obtains the bundle through this endpoint and uses it for the mTLS `/Marti/api/version` probe instead of the hand-built CSR, proving CloudTAK's own parser path (`@tak-ps/node-p12`) accepts it — if that library is not in the tree, parse with `node-forge` (check what node-tak already depends on before adding anything).
5. **Docs**: `docs/deployment.md` CloudTAK section (replace the manual recipe with the button), one README highlight sentence, `compat/cloudtak.md` note, `.claude/plan/backlog.md` (nothing to remove unless listed).
