# M0-20 — Remove native OpenSSL from the passkey stack

**Problem.** `webauthn-rs` 0.5.5 (workspace dep, features `danger-allow-state-serialisation`, `danger-credential-internals`, `conditional-ui`) depends on the `openssl` crate, so every CI cross-build (`*-linux-musl`, `windows-msvc`, darwin) fails in `openssl-sys`' build script, and the binary would link libssl — against the project rule that TLS/crypto is rustls/RustCrypto only (`.claude/plan/conventions.md`). `cargo tree -i openssl-sys --workspace` must end up empty. The crate is used only in `rustak-server/src/auth/{passkeys,passkey_store}.rs` (plus the JSON handlers in `web/api/passkey.rs` and the software authenticator in `testing/authenticator.rs`), so this is a contained swap.

**Contract to preserve (do not change the wire format or the UI/e2e):** `POST /api/v1/auth/passkey/register/{start,finish}` and `.../login/{start,finish}` keep their request/response JSON exactly as `rustak-api` and `rustak-ui/src/auth/passkey.rs` define it (standard WebAuthn JSON: `publicKey` creation/request options with base64url fields; `PublicKeyCredential` JSON back). Registration: attestation `none`, `residentKey: "required"` + `requireResidentKey: true`, `userVerification: "required"`, algorithms ES256 (-7), RS256 (-257), EdDSA (-8), exclude list of the user's existing credentials. Login: discoverable (empty `allowCredentials`) **and** username-assisted (`allowCredentials` for that user) ceremonies, UV required, sign-count regression detection (record, warn, do not hard-fail unless the count went backwards from a non-zero value — document), backup-eligible/backed-up flags stored, RP ID = configured host, origin check against the configured base URL(s) with the same semantics as today (`auth::passkeys` tests spell them out). Pending ceremony state stays in the existing DB-backed store (`passkey_store.rs`) with the same TTL; credential rows keep their schema (no new migration unless unavoidable — if you need one, add `0008_*.sql` and update the migration tests). `auth::passkeys::require_discoverable` semantics from M0-18 stay.

**Approach, in order.** (1) Evaluate `webauthn-rp` 0.3 (pure Rust, MIT/Apache-2.0): if it covers the contract with `serde`/`serde_relaxed`, use it. (2) Otherwise implement a minimal relying-party verifier in-house on RustCrypto: `ciborium` (CBOR attestation object/authData), `sha2`, `p256` (ECDSA P-256, `ecdsa` verify), `rsa` (PKCS#1 v1.5 SHA-256), `ed25519-dalek`; parse `clientDataJSON` (type, challenge, origin, optional `crossOrigin`), authData (rpIdHash, flags UP/UV/BE/BS/AT/ED, signCount, attested credential data with COSE key), reject unknown COSE algorithms, constant-time challenge compare, strict base64url. Keep it under 300 functional lines per file (`auth/webauthn/{mod,cose,authdata,client_data,verify}.rs` is a reasonable split) with unit tests using fixed vectors generated by the software authenticator, plus negative tests (wrong origin, wrong RP ID, UV missing, tampered signature, replayed challenge, unknown alg). (3) Vendored OpenSSL is **not** acceptable. Whichever route you take, record the decision and the trade-offs in your status file and one line in `docs/deployment.md` if operator-visible behaviour changed.
