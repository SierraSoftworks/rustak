# M2-13 — `[web.public.tls] mode = "files"`: reload on change and tolerate files that arrive later

**Context.** An operator deploying rustak on Nomad renders a Tailscale/Let's Encrypt certificate to disk from a sidecar; the files appear *after* the task starts and are renewed every ~60 days. `config.example.toml` says the files are "reloaded when they change", but `web/tls.rs::from_files` loads them once at start-up and there is no watcher; a missing file at start-up is a hard failure. ACME mode already publishes a swappable `CertifiedKey` through `pki/tls/resolver.rs`.

**Read first:** `.claude/plan/conventions.md`, status `M2-10-acme.md` (the resolver slot, `web::tls::resolve`, `settings/tls` status DTO), `M0-12-runtime-bootstrap.md`, `rustak-server/src/{web/tls.rs,pki/tls/resolver.rs,jobs/acme_renew.rs,config/web.rs}`, `docs/deployment.md` → TLS modes.

**Deliver.**
1. `mode = "files"` serves through the same resolver as ACME: at start-up, if the files are missing or unreadable, log a `WARN` naming the paths, bind with the internal-CA certificate (exactly as ACME's bootstrap does) and keep the listener up; a job (`jobs/tls_files.rs`, every 30 s, cheap `stat` on mtime/size/inode) loads the pair when it appears or changes, validates that the key matches the certificate and the chain parses, then swaps it in atomically; a broken new pair is logged and ignored (the previous one keeps serving). Optional inotify/kqueue is not required — polling is fine and portable.
2. `GET /api/v1/settings/tls` reports the files mode too (`source: "files"`, paths, loaded-at, not-after, "waiting for files" while bootstrapped on the internal certificate); `POST /api/v1/settings/tls/renew` in files mode forces a reload.
3. Config: `[web.public.tls] reload_interval` (default `30s`, `0` disables), `require_files_at_start = false` default (set `true` to keep today's fail-fast behaviour); validation and `config.example.toml` text corrected so it matches the code.
4. `docs/deployment.md`: the TLS modes section describes the behaviour (first deploy with a sidecar-issued certificate, renewals without restart, how to confirm via `/api/v1/settings/tls` and the log line).
5. Tests: swap-on-change with a temp dir (write pair A, start, replace with pair B, assert the resolver serves B and the status changed); missing-at-start then appears; mismatched key/cert ignored; `require_files_at_start = true` fails fast.

**Files you own:** `rustak-server/src/web/tls.rs`, `pki/tls/resolver.rs` (additive), `jobs/tls_files.rs` (+ `jobs/mod.rs` line), `config/web.rs`, `config/validate.rs` (TLS rules only — another agent is editing this file; re-read immediately before editing and keep the hunk small), `web/api/settings.rs` (files-mode branch only; the security agent owns other parts of `web/api/**` — re-read before editing), `rustak-api/src/settings.rs` (additive fields), `config.example.toml` (the `[web.public.tls]` block), `docs/deployment.md` (TLS section), tests, your status file. No `git`/`but` writes; files < 300 functional lines. Exit checks: the standard set plus `--check` on `config.example.toml` and on a `mode = "files"` config whose files do not exist (must pass validation with the default).
