# M9-09 — AISStream delivers JSON in binary WebSocket frames; the AIS source discards them

**Why — production finding, 2026-09-21 (Dublin).** `rustak-plugin-ais` subscribed to AISStream cleanly ("Subscribed to the AIS stream.") and then tracked nothing for minutes over Dublin Bay. `rustak-plugin-ais/src/sources/aisstream.rs` (~line 210) matches `Message::Text` → `deliver`, `Message::Ping`, `Message::Close`, and sends every other frame to `debug!("A frame this source does not read.")`. AISStream sends each JSON message as a **binary** frame (its own client examples read bytes and JSON-decode them), so every position report is silently dropped. Separately, `deliver` swallows anything that is not a known envelope at `debug`, which includes AISStream's error replies (e.g. `{"error": "Api Key Is Not Valid"}`), so a bad key would look identical to a quiet sea.

**Deliver (AIS plugin only).**
1. Treat `Message::Binary(bytes)` exactly like text: decode as UTF-8 JSON and `deliver` it (a frame that is not UTF-8 is counted and skipped). Keep `Text` working.
2. Surface AISStream error replies: a JSON object with an `error` key (check `wire.rs` and the public docs for the exact shape; match case-insensitively on the key) becomes a source failure — `warn` once with the server's text (never the API key), the connection state goes to failed/reconnecting with that reason so the heartbeat shows it, and the reconnect backoff applies (an invalid key must not spin).
3. Count what is dropped: `source.frames_undecoded` and `source.messages_ignored` in the heartbeat metrics (the `FeedStatus`/`status.rs` builder), and when the source has been connected for 2 minutes with zero decoded position reports, one `warn` saying so with both counters — a silent feed must never again be indistinguishable from an empty one.
4. Tests: the frame loop factored so a unit test can feed it `Binary` and `Text` frames carrying your own hand-written PositionReport JSON and assert an `Observation` comes out of each; an error reply becomes a failure with the server's text and without the key; non-UTF-8 binary is counted, not fatal; the 2-minute silent-feed warning fires once (controllable clock or the state machine, not log capture).
5. README: one sentence in the AISStream section (frames may be text or binary; error replies are reported on the Services page).
