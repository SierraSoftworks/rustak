**Deliver.**
1. `rustak-server/src/files/{store,metadata,legacy,search}.rs` (+ `mod.rs`): streaming ingest into the existing `ContentStore` (hash while streaming to a tmp file, size limit from `[marti] upload_size_limit`, dedupe on hash), `resources` repo (`db/repos/resources.rs` if the M0 repo layer has none), the visibility rule (admin ∨ `groups` ∩ caller OUT groups ∨ submitter; empty groups ⇒ `__ANON__`), the legacy Title-case `Metadata` view (`PrimaryKey`/`Size` as strings, `EXPIRATION` always present, `SubmissionDateTime` padded millis), the `Resource` JSON view, and the `/files/metadata` map-of-strings view (`Size` humanised, `Time` in Java `Date.toString()` style). Uploaded bytes never load fully into memory.
2. `rustak-server/src/marti/{sync,sync_metadata,files}.rs` implementing the §5.2 table exactly: `POST /Marti/sync/upload` (multipart `assetfile|resource` or raw body; `text/json` legacy Metadata response), `GET /Marti/sync/search` (`{resultCount, results}` as `text/json`), `GET|HEAD /Marti/sync/content` (streamed from disk, `api-version: 3`, `Content-Disposition: inline; filename=…`, `offset`/`length`/`Range` ⇒ 206, HTML 404), `POST /Marti/sync/missionupload` (multipart only, `filename` required, `Groups`/`groups`, dedupe, `text/plain` URL built from `[marti] public_host` or the request Host), `GET /Marti/sync/missionquery`, `/Marti/sync/delete` (GET/POST/DELETE, TAK's HTML body), `PUT /Marti/api/sync/metadata/{hash}/{tool|mimetype|keywords|expiration}`, `GET /Marti/api/sync/search` (Resource JSON), `GET /Marti/api/files/metadata` (+`/count`), `GET|HEAD|DELETE /Marti/api/files/{hash}`, `PUT /Marti/api/files/{hash}/metadata`. Register in `marti/mod.rs` with **one** `.configure(...)` line per new file and a `.default_service()` on any new nested scope. Never emit `application/json; charset=…`; never 3xx.
3. Audit entries for upload/delete/metadata changes (`audit_log`, existing store). `tracing` spans per handler; never log file contents.
4. Tests: unit tests per file; a contract suite `rustak-server/tests/sync_contract.rs` asserting exact bodies/headers for each endpoint (CloudTAK reads `Hash`, `Groups`, `Time`; ATAK needs `resultCount`, `UID`, `Name`, `Hash`, `PrimaryKey` int-parsable, `SubmissionDateTime`); an upload of a multi-megabyte synthetic body proving streaming (no full buffering — assert via the tmp-file path or a bounded reader).
