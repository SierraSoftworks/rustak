# M7-02 — A scheduled sweep for stale CloudTAK hand-over bundles

**Why.** `identity::cloudtak::sweep` runs only when the next hand-over is prepared, and the ten-minute expiry is enforced on read, so a stale bundle is never *served* — but on an installation that onboards CloudTAK once, one sealed, passphrase-protected keystore sits in `kv` indefinitely. M5-03 left it because `jobs/` was outside its files. Close it with a recurring job.

**Read first:** `.claude/plan/conventions.md`; `rustak-server/src/jobs/mod.rs` (module doc: "Recurring work" — the arm-in-`setup`, re-arm-at-top-of-`handle` shape); `jobs/audit_prune.rs` and `jobs/content_orphans.rs` as the two closest templates (the second has a grace period); `identity/cloudtak/{mod,bundle}.rs` (`stash`, `take`, `sweep`, `BUNDLE_PARTITION`); status M5-03; `rustak-server/tests/cloudtak_onboarding.rs` (has an expiry test you can build on).

**Deliver.**
1. `jobs/cloudtak_sweep.rs`: a recurring job (`CLOUDTAK_SWEEP_PARTITION`, `CloudTakSweepJob`, `CloudTakSweepTask`, `SWEEP_INTERVAL`) that calls `identity::cloudtak::sweep` every 15 minutes (the bundle TTL is 10) and logs the count removed at `debug` (nothing when zero). Register with `register_job!`; re-export from `jobs/mod.rs` like its siblings. No config knob unless the other sweeps have one — match them.
2. If `sweep` needs a signature change to be callable from a job (it takes what today?), make it additive.
3. **Tests**: a unit test for the job following `audit_prune.rs`'s pattern (arms itself, removes an expired bundle, leaves a live one), and one integration assertion in `tests/cloudtak_onboarding.rs` that a bundle past its TTL disappears from `kv` after the job runs, not only on the next hand-over. Prove the job is registered (whatever the host's registry test does for the others).
4. `docs/deployment.md` has a CloudTAK onboarding section with a sentence on the ten-minute expiry — only if it claims the bundle is deleted on expiry, make that sentence true (it is now); otherwise leave docs alone.

**Files you own:** `rustak-server/src/jobs/cloudtak_sweep.rs` (new), `rustak-server/src/jobs/mod.rs` (additive lines only — M7-01 does not touch it, but keep the diff minimal), `rustak-server/src/identity/cloudtak/**` (additive), `rustak-server/tests/cloudtak_onboarding.rs`, one sentence in `docs/deployment.md` if needed, your status file.
