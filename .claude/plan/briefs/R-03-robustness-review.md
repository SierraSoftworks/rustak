# R-03 — Independent robustness review: storage, runtime, concurrency, resource limits

**Role.** Reviewer, not implementer. Read-only; one report. Read `.claude/plan/conventions.md`, design 01 §4 (storage) and §5, design 02 (hub/router/writer queues), status files M0-07, M0-08, M0-10, M0-12, M0-19, M1-05, M3-01, M4-01, M4-02, M6-01, M2-11. Then the code: `rustak-server/src/{db/**,store/**,cot_store/**,stream/{hub,router,connection,writer,listener_tls,live,registry}.rs,files/**,jobs/**,runtime.rs,services/**,plugins/events.rs}`.

**Look for:** SQLite writer starvation or long transactions on the router path; anything awaiting under a `parking_lot` guard; unbounded channels, queues, or the SSE ring; per-connection memory under a slow reader; append-log crash-safety (torn frames, index lag, retention deleting a live segment); content-store temp files leaked on error; multipart uploads buffered in memory; missing size limits (XML/protobuf frame caps, upload cap, request body caps on `/api/v1`); shutdown ordering (drain, checkpoint, abort); job host retries and poison jobs; migrations that are not idempotent or that lock; `Database::close` on error paths; blocking I/O on the async runtime (`std::fs`, `zip` on large packages); unbounded `join_all`s; timeouts missing on outbound HTTP (ACME, OIDC, SSE consumers); anything that would make a 400 MB package or 500 connected devices misbehave.

**Deliver** `.claude/plan/reviews/R-03-robustness-review.md`: findings by severity with file:line, a failure scenario for each, and the fix; then the load/soak tests you would add (with rough numbers). No `git`/`but` writes; do not edit source. Return the findings summary.
