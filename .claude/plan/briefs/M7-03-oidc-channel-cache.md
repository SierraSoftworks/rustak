# M7-03 — A channel created by an OIDC sign-in tells the stream at once

**Why.** M2-14 made `identity::groups::{create,patch,delete}` invalidate the in-memory routing cache (`GroupCache`) immediately, but `apply_claims` → `lookup_or_create` (`identity/groups.rs:214`, `:303`) still takes `&Database` because `identity/users.rs` does, so a channel auto-created from an OIDC `groups` claim waits for the sub-second refresh, and — more to the point — a membership change applied from claims on sign-in may too. Close the gap so every path that changes channels or memberships notifies the same way.

**Read first:** `.claude/plan.md` → Identity & auth model (group claim mapping: bare ⇒ IN+OUT, `_READ` ⇒ OUT, `_WRITE` ⇒ IN); status M2-14 (what it changed and why this was left), M5-01 (OIDC federation and the auto-create path), and the later "OIDC account linking" commits on `main` (`abba577`, `ec7320f`, migration `0017_user_claims.sql`) which touched `identity/users.rs` after M2-14 — read them before assuming the shape; `identity/{groups,users}.rs`; `auth/oidc/**` and `web/api/auth*.rs` for every caller of `apply_claims`; `stream/` for the `GroupCache` invalidation handle the M2-14 paths use (find what `groups::create` calls).

**Deliver.**
1. Route the claim-driven path through the same invalidation as the admin API paths: either `apply_claims`/`lookup_or_create` take the same handle `groups::create` takes (preferred if the callers already have `Services`), or the caller invalidates after `apply_claims` returns a "changed" flag. Whichever keeps `identity/users.rs` free of stream types. Membership changes from claims (added/removed IN/OUT) must invalidate too, not only channel creation.
2. Make sure a user whose claims *removed* a channel loses reachability on their live stream connections within the same request (M2-14's `t-x-g-c` and reachability recompute apply here as well — reuse, do not duplicate).
3. **Tests**: an integration test with the in-process `TestIdentityProvider`: sign in with a `groups` claim naming a channel that does not exist, assert the channel exists *and* a fake EUD's routing reflects it without waiting for the refresh interval (set the refresh interval high in the test config, or whatever M2-14's tests do to prove immediacy); a second sign-in with the channel removed from the claim revokes reachability the same way.
