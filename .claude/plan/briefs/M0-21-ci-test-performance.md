# M0-21 — Make the test suite fast under coverage on CI, and fix the new clippy failure

**Symptoms (CI run 35358709048 and every run since the server batch landed).** `cargo test --workspace --no-fail-fast` with `RUSTFLAGS=-Cinstrument-coverage` on a 2-vCPU `ubuntu-latest` runner never finishes: individual `web::api::{groups,devices,me,passkey}::tests::*` cases take 30–60 s each ("has been running for over 60 seconds"), while the same 1200 tests finish in ~17 s on the developer machine. Separately, the Lint job fails on CI's newer stable clippy with `result_large_err` at `rustak-server/src/marti/tls.rs` (`async fn caller(...) -> Result<(Resolved, Arc<Pki>), HttpResponse>`).

**Diagnosis to confirm, then fix.** Every `TestServer` (`rustak-server/src/testing/context.rs`) mints a fresh RS256 `JwtIssuer` (`auth/jwt.rs:148` generates a 2048-bit RSA key per instance) and many suites also build a fresh `pki::testing::TestAuthority` (RSA-2048 root + server certificates via `pki::keys::generate_key`), and credentials/passkey tests run argon2id at production parameters. Under `-Cinstrument-coverage` (which also instruments `rsa`, `num-bigint-dig`, `argon2` despite the `opt-level = 3` overrides in the workspace `Cargo.toml`) each keygen costs seconds and the runner has two cores. Measure first: `cargo test -p rustak-server --features testing -- -Z unstable-options --report-time` is nightly-only, so instead add a temporary `tracing`/`eprintln` timing around `TestServer::new` and `TestAuthority::new`, or count calls, and record numbers in the status file before and after.

**Deliver.**
1. **Process-wide cached test key material** in the `testing` module: one `LazyLock` RS256 key pair for `JwtIssuer` (add `JwtIssuer::from_private_key(...)`/`with_key` if it only has a generating constructor), one `LazyLock` root CA + server certificate set for `TestAuthority::new()` (clone the material per test; keep `TestAuthority::fresh()` or `foreign()` for the handful of tests that need a *different* authority and make those use ECDSA P-256, which is cheap). Test isolation must not change: databases and data dirs stay per test. Production code paths keep generating keys; only `testing`/`cfg(test)` code is affected.
2. **Cheaper argon2 in tests**: introduce `rustak_core::identity::password::Params` (or reuse the existing type) with a `testing()` preset (e.g. m=8 MiB, t=1, p=1) selected by the `testing` feature / `cfg(test)` where `TestServer` builds its config, never in production defaults. Add `[profile.dev.package.argon2] opt-level = 3` (and `blake2`/`sha2` if profiling shows them) to the workspace `Cargo.toml`.
3. **CI guard rails** in `.github/workflows/rust.yml`: `timeout-minutes` on every job (test 30, build 45, others 20), and keep coverage on (do not drop `-Cinstrument-coverage`); if after 1–2 the Test job still exceeds ~10 minutes, set `RUSTFLAGS` so that only workspace crates are instrumented (`-Cinstrument-coverage` is per-invocation; the standard trick is `cargo llvm-cov --workspace --no-cfg-coverage` or `RUSTFLAGS` plus `CARGO_PROFILE_TEST_*`; pick the simplest that works and document it in `docs/ci.md`). Also correct the stale `interop-node-tak` job comment (it still lists M2-06 among skipping milestones).
4. **Clippy**: fix `result_large_err` in `marti/tls.rs` by boxing the `HttpResponse` error (`Result<_, Box<HttpResponse>>`) or returning `MartiError` and rendering the challenge at the edge — whichever keeps the plain-text `WWW-Authenticate` contract intact (tests exist). Run clippy with the **current stable toolchain** (`rustup update stable` has been run on this machine; check `cargo clippy --version` is ≥ 1.97) so CI and local agree; fix anything else the newer clippy reports across the workspace.
5. Verify locally: `time cargo test --workspace` before/after; `RUSTFLAGS=-Cinstrument-coverage cargo test -p rustak-server --features testing` completes (record wall time); `cargo clippy --workspace --all-targets -- -D warnings` clean on the new toolchain; the full exit-check set from `.claude/plan/conventions.md`.
