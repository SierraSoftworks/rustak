# M9-04 — Let a sidecar's own heartbeat reach the Services page (the harness must stop overwriting it)

**Why.** M9-02 found that `rustak-client/src/sidecar/run.rs` sends `Heartbeat::healthy()` unconditionally after every `Sidecar::tick`, and the server writes state, message and metrics wholesale on each heartbeat. So a plugin that reports `degraded`, a message and `FeedCounters` (both M9-01 and M9-02 build such a heartbeat) is overwritten a moment later and the new Services page (M9-03) shows plain `healthy` with no metrics. The SDK needs one hook so the plugin's report is the heartbeat.

**Read first:** `.claude/plan/conventions.md`; `rustak-client/src/sidecar/{mod,run,control_link}.rs`; `docs/plugins.md` → "Saying more than healthy" and "Monitoring a sidecar" (M9-03); status M6-01 (heartbeat semantics, `plugins::health::record`), M9-02 (`rustak-plugin-adsb/src/health.rs` and how it currently tries to report) and M9-01 (the AIS equivalent); `rustak-server/tests/{services_flow,feed_sidecars}.rs` and `tests/feed_support/mod.rs`; `rustak-api/src/service.rs` (`Heartbeat`, `ServiceState`).

**Deliver.**
1. **The hook.** `Sidecar` gains `async fn health(&mut self, ctx: &SidecarContext<Self::Settings>) -> Option<Heartbeat>` (name and signature to match the trait's existing style; default implementation returns `None`). The harness, after each tick, sends the plugin's heartbeat when `Some`, otherwise `Heartbeat::healthy()` exactly as today. If a plugin also calls `control.heartbeat` itself, the harness must not clobber it within the same tick — the simplest rule is: the harness sends only when the plugin did not report during that tick (track it on the control link), and document which of the two mechanisms is preferred (the hook).
2. **Adopt it** in `rustak-plugin-adsb` and `rustak-plugin-ais` (their `health.rs` builders become the hook's body; delete any direct heartbeat send they added to work around the harness) and mention it in `rustak-plugin-example` only as a doc comment (the example stays minimal).
3. **Tests.** In `rustak-server/tests/services_flow.rs` (or a new case in `feed_sidecars.rs` via `feed_support`): a sidecar whose `health()` returns `degraded` with a message and metrics is listed by `GET /api/v1/services` with exactly that state, message and metrics after one tick, and stays so after a second tick (the harness did not overwrite it); a sidecar with the default hook is listed `healthy`. Also add the case M9-02 could not: `feed_sidecars.rs` drives `rustak-plugin-adsb` with its `Readsb` source over a `wiremock` URL serving the crate's fixture and asserts the CoT on the fake EUD (three lines with the existing helper, per M9-02's status).
4. **Docs.** `docs/plugins.md`: rewrite "Saying more than healthy" around the hook, keep the direct call as the escape hatch; the "Monitoring a sidecar" section says the hook is what the page renders.
