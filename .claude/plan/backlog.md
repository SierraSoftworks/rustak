Found by them:

- **A peer that vanishes mid-write is still `write_error`.** M10-01 classified the read side only; a broken pipe or reset on a write is the same departure and should read `client_vanished` (`rustak-server/src/stream/writer.rs`, through `peer_probe::cause`). Found by M10-01.
- **A plugin error that ends the harness loop exits without closing the stream**, so the server records `client_vanished` for a sidecar that crashed out of `tick`. Close on that path too (`rustak-client/src/sidecar/run.rs`). Found by M10-01.
- **No test blackholes a peer.** It needs a firewall rule, a network namespace or `TCP_REPAIR`, all privileged; M10-02 proves the socket options by reading them back and the `ETIMEDOUT` mapping by unit test. A nightly job with `sudo` and a network namespace on the Linux runner could prove the reclaim end to end.
- **ESB and FIRMS publish no `config_schema`**, so the Services page draws no form for their `area` override the way it does for AIS and ADS-B. Found by M10-04.
- **Slow pollers remind once per attempt**: with attempts more than five minutes apart (FIRMS by default) every failed attempt in a long outage is its own reminder line. Consider a reminder interval that is a multiple of the poll. Found by M10-04.
- **Userinfo for a grant without `openid`**: a client granted `profile email` but not `openid` gets no ID token, yet userinfo releases those claims. OIDC does not define the case; the narrow answer is `sub` alone. Found by M10-06.
- **A response that breaks off mid-body counts as the control link being down** (as every transport failure did before M10-03). If it should count as the server answering, it is one line in `rustak-client/src/http/failure.rs` `OUTAGES`.
- **Negative checks that prove less than they claim** (M10-08's audit, files it did not own; details in its status note). Most `SETTLE` (400 ms) checks can only pass wrongly on a slow host, because nothing shows the message was routed before the wait ran out: `stream_routing` (five sites), `stream_store` (two), `marti_channels`, `stream_session` (two). The cure is the barrier `mission_dest::first_after` uses: send a second, allowed message and assert it arrives first. A few can fail wrongly: `marti_channels`' `drain()`, fixed sleeps before a negative check (`stream_session.rs`, `stream_routing.rs`), 150 ms drains in `stream_channel_state.rs` and `stream_routing.rs`.
- **Waits bounded by a poll count rather than a deadline**: 200-poll loops in `marti_channels` `await_only`, `stream_store.rs`, `api_v1_map.rs` and `workload_identity.rs`; the 2 s real-clock idle timeout in `stream_idle`; the 250 ms `SETTLE_BUDGET` in `Eud::send` (`rustak-client/src/stream/testing.rs`). Found by M10-08.
- **The plugin guide says an enrolled sidecar needs no token for the control API; it does.** `/api/v1` is served only by the public listener, which never asks for a client certificate, so a sidecar without workload identity needs a service token (`docs/plugins.md` "Three credentials", the `rustak-client` control module doc). Either correct the documents, or let the public listener accept an optional client certificate and retire the service token for enrolled sidecars. Found by M10-12.
- **A rotation that fails part-way is not strictly all-or-nothing** in service onboarding: the new token is revoked, but an old token already revoked stays revoked. Found by M10-12.
- **Feed plugins disagree in four small ways**, each kept as a `Rules` parameter by M10-13 rather than decided: whether the floor stays raised after repeated stated `Retry-After`s (ADS-B yes; ESB/FIRMS return to `poll`); whether a 429 is an answer (FIRMS yes); when a refusal run settles (5 min, or `max(5 min, 3 × poll)`); the `Retry-After` ceiling (5 min ADS-B, 1 h ESB/FIRMS). And a configuration with no `area` gives the choice back to the file in ESB/FIRMS but keeps the current area in ADS-B.
- **`code_grant.rs` keeps its own `oauth-client:` prefix**, duplicated as `ratelimit::CLIENT_PREFIX` by M10-11; point one at the other. Six integration harnesses still build their own `RateLimiter` (harmless). R-01 L1 still stands: a guesser spread across many addresses is counted per account now, not stopped.
- **The preference catalogue is short on purpose** (13 keys, each cited from `research/` or `compat/`): 14 keys the old list carried were dropped because nothing in the repository cites them, and ATAK's public documentation was not consulted. Grow it from a cited source. The per-host keys `prefs_enable_channels_host-<host>` and `prefs_enable_channels_hierarchy_host-<host>` are key *patterns* and need a pattern entry. Found by M10-14.
- **A duration control for the schema form** (a number with a minutes/hours picker that writes `"3h"`) would let `probe_max_wait` use one key and one format in the file and on the Services page; today the page edits `probe_max_wait_minutes`. Showing an empty optional field's `default` as its placeholder would also help. And the server validates only the schema's range when the sidecar is down, so a value below the source's floor is saved and then ignored with a warning. Found by M10-15.
- **Bring the `Test` job's `timeout-minutes` down from 90.** Measured on `main`: 25m46s under `cargo test` (597f7c23, `Run tests` 23m44s); 20m59s under nextest (03b09f0e, 18m17s); **10m09s** with the test keys shared (f1fae703, run 36656965131: `Run tests` 7m21s = 3m47s compiling + 208 s running 3,875 tests, doctests 59 s, grcov 70 s). - **The rate limiter scans its whole map on every new key once it is full** (production, found by M10-17): at the 100,000-entry ceiling `RateLimiter::make_room` runs on each new-key insert and ignores the sweep schedule, so every further failure during a flood is a full scan under the mutex — the cost the sweep schedule removed from checks, now on the failure path. Bound it the same way (evict in batches, or on the schedule) and prove it by counting scans.

## Needs a maintainer decision or an upstream release
- **Shared `target/` fills the disk on macOS**: the dev profile's default `split-debuginfo = "unpacked"` keeps every codegen unit's `.o` file under `target/debug/deps` as the debug-info carrier (509k files, >100 GB after a day of parallel agents). Decide with the user: `[profile.dev] split-debuginfo = "packed"` (dsymutil per binary, small dSYMs, slower links) or `debug = "line-tables-only"` plus periodic `find target/debug/deps -name '*.o' -mmin +60 -delete`. Until then the orchestrator prunes `.o` files older than an hour before each landing.
