- **A peer that vanishes while the server is still writing to it is now reclaimed by TCP, not by the idle timer** (M9-15). The idle rule became `max(last_rx, last_tx)` so that receive-only clients survive, and a completed write only proves the bytes reached the kernel. A phone that drops off the network on a busy channel therefore stays registered — and shows as connected in contacts — until the send buffer fills and `write_timeout` fires, or the kernel gives up retransmitting (about 15 minutes on Linux defaults); before M9-15 it was gone in `idle_timeout`. The stream listener sets `TCP_NODELAY` and nothing else. Set `SO_KEEPALIVE` with short probes and `TCP_USER_TIMEOUT` (Linux) on accepted sockets in `stream/listener_tls.rs`, sized from `idle_timeout`, so a ghost is bounded to roughly the old 90 s without the server having to ping. Prove it with a test that blackholes a peer rather than closing it.
